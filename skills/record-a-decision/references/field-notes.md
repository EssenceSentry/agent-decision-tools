# Resolve and record a commitment

Use these procedures when a decision spans contributors or sessions.

<a id="decision-record"></a>

## Record the decision at its revision

Name the owner, date, status, actual alternatives, reason, accepted cost and excluded scope. Link the current guarantee and evidence at a specific revision. Link replacements in both directions and preserve the earlier decision as historical.

<a id="decisions-and-traps"></a>

## Make a failed route searchable

Record symptom, attempted approach, decisive evidence and when that route becomes worth trying again. Link the decision that followed and name the next unresolved choice.

<a id="two-list-map"></a>

## Apply the right update rule

Record whose need would change and what trade they accept. For each technical hypothesis, name evidence, dependencies and a falsifier. At the next expensive commitment refresh only the entries whose revision could change the action.

<a id="wayfinder-layout"></a>

## Keep an index a new session can open

Start with destination and exclusions. Link accepted decisions by name. For each open question give what blocks it and the next useful action. Keep detail in the owning record so updates have one home.

<a id="wayfinder"></a>

## Find the next resolvable decision

Distinguish a precise question blocked by another decision from an area too vague to formulate yet. Keep the former as a dependency and the latter under “not yet specified.” Select an unblocked, unclaimed question. When resolved, update the map and ask what has now become specific enough to investigate. For multi-writer work, record an owner before two people start the same job.

<a id="adr-skill"></a>

## Search, create, consult and supersede a record

Search existing decisions for the same scope, read their current status and locate the replacement of any superseded record. To create the first or a later record, use the [bundled generator](decision-record.md) with the project’s directory and optional index. Fill the draft, remove placeholders, check its links and accepted costs, and preserve old rationale when adding a replacement. Follow the local convention for acceptance and filenames.
