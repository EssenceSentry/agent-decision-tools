# Working out a better frame

Use these moves when a proposal sounds plausible but its cost, beneficiary or acceptance condition is unclear.

<a id="code-admission"></a>

## Walk a real caller through removal

Compare deletion, a short rule or recipe, and a shared component. Identify a repeated correctness failure, a substantial tested algorithm or a shared invariant that the component alone buys. Include the changes each choice imposes on consumers.

<a id="problem-variants"></a>

## Carry a result back from a variant

Write unknown, data and conditions. Produce two or three variants by different moves: a special case, the direction of reasoning reversed, the obstructing condition relaxed. Work each far enough to get a result. For each, identify precisely which part of the result transfers back and which breaks when the original constraint returns. Lay the variants beside the problem as stated, in the same terms, before recommending one.

<a id="relax-one-requirement"></a>

## Price the smallest useful relaxation

Change one condition with the others fixed. Identify its owner, who receives the gain, who pays the loss, and the value at which the owner would prefer the alternative. Show the owner the requirement as stated and the relaxed version side by side, with what each delivers and costs. Preserve binding terms until the owner changes them.

<a id="to-spec"></a>

## Turn the conversation into acceptance examples

Use the project glossary and existing decisions. Write the user-facing problem and solution, actor and benefit for materially different stories, the public behavior, testing seam, non-goals and unresolved decisions. Preserve a decision-rich schema or transition from a prototype where prose would be ambiguous. Link existing tests.

<a id="issue-redefinition"></a>

## Change the unit of the question

Restate the owner’s exact question. Try changing actor to system, threat to vulnerability, immediate event to trend, or explanation to intervention. Invert or resize the boundary if that exposes a different action. Record which evidence becomes relevant and select one working formulation. Two phrasings leading to the same evidence and action are redundant.

<a id="brainstorming"></a>

## Play the design back to its builder

Read existing work before asking. Work out concrete alternatives and explain the trade in the owner’s words. Read the proposed design as its builder with only that document. Rank unanswered questions where a wrong guess changes the plan. Leave delegated and reversible implementation details to the builder. For a visual choice, show alternatives on the same task and record which difference mattered to the owner.

<a id="think-problem-restatement"></a>

## Change viewpoint before choosing the frame

Capture the original wording and the assumption it embeds. Move up to the purpose, down to the observed failure, switch affected stakeholder or invert the desired outcome. Explain in one sentence which alternative would produce a genuinely different action and why it serves the actual goal.
