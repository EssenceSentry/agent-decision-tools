# Methods from the planning discussion

The toolkit covers the recurring, inexpensive decisions in the research and coding workflow. This table distinguishes the executable implementation in this repository from the specialist software discussed for larger problems.

| Method | What runs here | When the original method adds something |
|---|---|---|
| Forward Fermi estimation | `fermi` delegates one small forward program to the pinned Squiggle language runtime. Programs can use empirical rows, distributions, sums, conditions and shared uncertain factors. | The skill explains how to select measurements and elicit grounded inputs. [Squiggle](https://www.squiggle-language.com/) |
| Finite decisions and value of information | `decide` enumerates finite states and observations, applies Bayes' rule and returns EVPI, partition-based EVPPI, EVSI and expected net benefit of sampling. | Use an influence diagram for factored dependencies and information available at each decision. The R package covers VOI estimation from richer probabilistic models. [pyAgrum](https://pyagrum.readthedocs.io/en/3.2.1/infdiag.html) · [GeNIe](https://www.bayesfusion.com/influence-diagrams/) · [R voi](https://cran.r-project.org/web/packages/voi/vignettes/voi.html) |
| Sensitivity and deep uncertainty | `robust` enumerates the supplied scenarios and reports minimax regret and maximin payoff. `breakeven` uses NumPy to price a probe from equally weighted savings draws. | Use scenario discovery to identify combinations of many uncertain inputs associated with failure. [EMA Workbench PRIM](https://emaworkbench.readthedocs.io/en/2.2.0/ema_documentation/analysis/prim.html) |
| Metareasoning | `decide` compares stopping now with buying a check and can condition a second purchase on the result. | General partially observable models can handle state transitions, longer horizons and dependent observations. [POMDPs.jl](https://github.com/JuliaPOMDP/POMDPs.jl) · [POMCPOW](https://github.com/JuliaPOMDP/POMCPOW.jl) |
| Sequential tests | `interim` uses SciPy exact binomial intervals with an allocation across prespecified looks. | Use a formally designed group-sequential trial for specific power, futility boundaries or alpha spending. An experiment platform may already supply its own sequential test. [SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binomtest.html) · [gsDesign](https://cran.r-project.org/web/packages/gsDesign/vignettes/GentleIntroductionToGSD.html) · [Statsig](https://docs.statsig.com/experiments/advanced-setup/sequential-testing) |
| Multi-fidelity evaluation | `decide` handles a discrete cheap pilot followed by a costly confirmation when their conditional observation behavior is supplied. | ADEMP specifies aims, data-generating mechanisms, estimands, methods and performance measures for a simulation study. BoTorch can select evaluations in repeated cost-aware optimization. [ADEMP](https://doi.org/10.1002/sim.8086) · [BoTorch](https://botorch.org/docs/tutorials/multi_fidelity_bo/) |
| Capacity and deadlines | `schedule` delegates interval selection, precedence and resource conflicts to OR-Tools CP-SAT. | Use the full solver for multi-resource jobs, variable durations, capacities or richer objectives. [OR-Tools](https://developers.google.com/optimization/scheduling/job_shop) |
| Expert elicitation and revisions | `panel` summarizes supplied probabilities and arguments and tracks revisions. It consumes responses already collected by the caller. | Use SHELF for facilitated elicitation and Delphi for structured independent rounds and feedback. [SHELF](https://shelf.sites.sheffield.ac.uk/software) · [Scalable Delphi](https://t-lorenz.com/projects/scalable-delphi/) |
| Forecast verification | `calibrate` scores individual and pooled forecasts on the same resolved questions. | Cooke's weights use seed-question calibration and informativeness. Applying performance weights warrants separate held-out validation. [Cooke's Classical Model](https://doi.org/10.1093/reep/rex022) · [ForecastBench](https://www.forecastbench.org/about/) |
| Argument mapping and prospective decisions | Store the question, options, reasons and evidence alongside the committed decision input. `revisit` evaluates declared signposts against later observations and identifies who should act. | Argdown and Vargdown support explicit argument graphs, OSF can register prospective plans, and adaptation pathways map longer sequences of triggers and responses. [Argdown](https://argdown.org/) · [Vargdown](https://github.com/wassname/vargdown) · [OSF](https://help.osf.io/article/330-create-a-preregistration) · [Adaptation pathways](https://uncertainfutures.github.io/theory/DAPP/) |
